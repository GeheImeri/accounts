- 版本：v0.1（草案）
- 类型：个人自用 · Android · 全离线
- 工作名：「Accounts」（可改，见第 13 节开放问题）
- 定稿状态：视觉方向采用 **E · 晨雾**（完整视觉规范见 `docs/03-晨雾视觉规范与设计定稿.md`）；Android 工程骨架已搭建（见根 README 与 `docs/04-构建与签名指南.md`）。本文档是功能需求的权威来源，视觉/落地细节以 03 号文档与工程代码为准。

## 1. 项目概述

### 1.1 一句话定位

一个**只为自己做的 Android 记账 App**：记账快、统计顺、界面干净、数据全在本地、永远免费。

### 1.2 背景与痛点 → 本产品对策

| # | 现有工具的痛点（用户原话归纳） | 本产品对策 |
|---|---|---|
| 1 | 普通功能都要收费 / 会员墙 | 自用开发，无任何收费点、无内购、无广告；不上架也可用 |
| 2 | 统计不方便 | 明确统计口径；一屏看懂月度收支与分类占比；支持任意日期区间、下钻 |
| 3 | 记账不方便 | 主路径目标：**3 秒 / 笔、点击 ≤ 3 次**；连续记账、模板、常用金额 |
| 4 | 界面花里胡哨 | 极简原则：单色低饱和、无运营位、无装饰动画、高信息密度 |

### 1.3 目标用户

- 本人（唯一核心用户）；架构上允许未来给家人共用一台设备（多账本属 P2+，不阻塞）。

### 1.4 非目标（明确不做，防止范围膨胀）

- ❌ 不做账号系统、云同步、多端（iOS/Web）——App 完全离线
- ❌ 不上架应用商店（初期直接安装 APK）
- ❌ 不做复式记账、资产管理、投资理财、信用卡应还等复杂财务功能
- ❌ 不做广告、积分、社区、皮肤商城等一切运营功能
- ❌ 不引入需要联网的 SDK（地图/推送/统计 SDK 一律不要）

## 2. 设计原则

| 编号 | 原则 | 含义 |
|---|---|---|
| P1 | 记账速度第一 | 打开即记账；主路径 ≤ 3 次点击、≤ 3 秒完成一笔 |
| P2 | 本地优先、隐私干净 | Manifest **不声明 INTERNET 权限**；数据只存本机 Room(SQLite) |
| P3 | 界面克制 | 无启动页、无广告位；Material You + 低饱和色；深色模式跟随系统 |
| P4 | 统计即答案 | 月度总览 5 秒内可读；口径与明细逐笔求和一致 |
| P5 | 数据可带走 | 一键导出 CSV/JSON；备份与恢复（换机、刷机不丢账） |
| P6 | 单人手维护 | 依赖最少（无第三方服务）、构建全自动（CI）、代码极简 |

## 3. 使用场景（用户故事）

- **US1** 午饭 23.5 元：打开 App → 输入 23.5 → 点「餐饮」→ 完成。接着记下一笔（连续记账态）。
- **US2** 发工资：切「收入」→ 输入 9000 → 点「工资」→ 完成。
- **US3** 月末看账：打开「统计」看本月支出总额、分类占比、环比上月。
- **US4** 查证："上个月餐饮花了多少？" → 统计页点「餐饮」下钻查看明细。
- **US5** 退款：网购退款 30 元 → 记一笔「收入-退款」，不干扰支出结构。
- **US6** 现金转银行卡：转账 500，两账户余额变化，但**不计入收支**、不进统计。
- **US7** 换手机：先备份 → 新机恢复，账目完整。

## 4. 功能需求

优先级：P0 = MVP 必须；P1 = 紧随其后；P2 = 可选增强。
每条含：描述 / 关键交互 / 验收标准。

### F1 记一笔（P0）

- 默认「支出」态；顶部 支出/收入 一键切换
- 金额：输入框自动弹出数字键盘，支持小数两位；金额为 0 时不可保存
- **点分类即保存**（金额 > 0 时）：保存后进入**连续记账态**——金额清空、分类与账户保留、轻提示，可连续录入多笔（小票批量场景）
- 备注可选（不弹窗，就地一行）
- 时间默认「现在」，可点开修改日期时间
- **时间规则（Q1 答复）**：① 显示层——记账页的"今天 HH:mm"实时取自手机系统时钟，每次进入/回到页面都重新读取，系统时间/时区变化立即反映；② 记录层——仅在点击保存那一刻把当时时间固化为时间戳写入流水，之后修改系统时间不会改动已记数据，只影响之后新记的流水；③ （可选增强 P2）若检测到系统时间异常导致保存时间晚于当前时间较多，保存前轻提示
- 账户默认上次使用的账户
- 验收：打开到保存成功 ≤ 3 次点击；保存的流水立即可在明细看到；全程无网络行为（用权限清单与抓包确认）

### F2 流水明细（P0）

- 按日分组的时间线；每组显示当日小计；每行显示 分类图标/名称、账户、备注、金额
- 月份切换：顶部「◀ 11月 ▶」
- 顶部聚合条：当前月份 支出 / 收入 / 结余
- 点击一笔 → 编辑页（改金额/分类/账户/时间/备注）、删除、**再次记账**（复制该笔为模板，改时间即存）
- 验收：任意历史记录可改可删；修正后统计数字同步变化

### F3 统计报表（P0）

- 周期选择：本月（默认）/ 上月 / 年度 / 自定义区间
- 总览卡：支出、收入、结余 + 较上一周期增减（百分比）
- （可选开关，Q3）**跨月结余显示**：默认关闭，仅显示本期收支；设置开启后，总览卡显示 期初结余（上月结转）+ 本期结余 = **累计结余**，口径见第 6 节
- 支出分类占比：环形图 + 排行榜（金额、百分比、条形占比）；**点击分类下钻**该分类在该周期的逐笔/逐日
- 趋势：月度视角下近 6 / 12 个月支出柱状图；可看收入线（同图对比可选）
- 收入同样有分类统计
- 验收：任意周期下，总览数字 = 明细逐笔求和（提供导出自查手段）；口径见第 6 节

### F4 分类管理（P0）

- 支出、收入两套分类；**预设默认集**（见下方），用户可增/改/排序/停用
- 图标用 emoji（零图标库依赖、体积小）；可配颜色
- **分类不可真删**（只可停用），历史流水永不悬空；分类停用后旧流水仍按原分类展示
- 预设支出分类（可裁剪）：餐饮、交通、购物、居住、日用、娱乐、医疗、学习、人情、旅行、其他
  预设收入分类：工资、奖金、理财、退款、红包、其他
- **分类数量不受限（Q2 答复）**：除预置集外可随时新增；图标用 emoji 任意选择（自带键盘表情即可输入，无图标库上限），可配颜色；记账首页只摆放 8~12 个高频分类，其余收入"更多"分页/搜索，保证首页简洁
- 验收：改分类/改颜色即时生效；停用后记账页不再出现该分类，历史数据不受影响

### F5 账户与转账（P1）

- 账户：现金、储蓄卡、支付宝、微信零钱 + 自定义；可设初始余额；可停用
- 每账户显示按流水推算的余额：初始余额 + 转入 − 转出 + 收入 − 支出
- 转账：从 A 到 B（金额、备注）；**转账不计收支**、不进统计，只影响两账户余额
- 验收：转账后两账户余额正确；当月统计不含该金额

### F6 记账效率增强（P1）

- 常用金额 chips：最近使用金额 / 高频金额，点选填入
- 快捷模板：用户自定义一键模板（例：「早餐 ¥8 → 餐饮」），记账页顶部一行，点一下即记完
- 连续记账模式（F1 中默认行为，可关）
- 明细「再次记账」（F2）
- 验收：录"每日早餐"类固定支出 ≤ 2 次点击

### F7 数据导出与备份（P1，重要）

- 导出 CSV：UTF-8 **带 BOM**（Excel / WPS 打开中文不乱码），列含 时间/类型/分类/账户/金额/备注
- 导出 JSON：全量（分类、账户、流水、转账），格式稳定
- 备份：一键生成备份文件到手机存储，可选择分享（网盘/电脑）；**恢复**支持覆盖还原
- 验收：导出文件电脑打开正常；备份 → 清数据 → 恢复，账目与设置完全一致

### F8 设置与偏好（P1）

- 默认支出账户；记账页分类排序跟随 F4
- 统计开关：「跨月结余（期初/累计结余）显示」开 / 关（默认关）
- 主题：跟随系统 / 浅色 / 深色
- 周起始日（影响统计里的"周"视图，若做）
- 入口：明细页右上角或记一笔页齿轮进入「设置」

### F9 搜索与筛选（P1）

- 关键词搜备注；按 分类 / 账户 / 类型 / 日期区间 组合筛选
- 验收：能搜到「房租」「机场」等备注关键词；筛选结果与统计联动口径一致

### F10 预算（P2，可选）

- 按月总额预算，或按分类预算；进度条展示；超支变色提醒
- 提醒走**本地通知**（无需网络；需申请通知权限，P2 再评估要不要）

### F11 扩展（P2，可选）

- 桌面小组件：主屏快捷记一笔
- 语音记账：Android 本地语音识别（中文离线识别效果一般，需先验证再决定做不做）

## 5. 数据模型（草案）

> 关键工程决策：**金额一律以「分」存 Long**（`amountCents`），避免浮点误差；仅展示层格式化。

### 5.1 表结构（Room Entity 概要）

**Category（分类）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long PK | 自增 |
| name | Text | 名称（餐饮…） |
| icon | Text | emoji 图标 |
| color | Long | ARGB |
| kind | Text | expense / income |
| sortOrder | Int | 排序 |
| enabled | Boolean | 停用 = false（不真删） |
| isDefault | Boolean | 是否预设分类（导出/恢复区分） |

**Account（账户）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long PK | 自增 |
| name | Text | 现金 / 储蓄卡… |
| initialBalanceCents | Long | 初始余额 |
| sortOrder / enabled | … | 同上 |

**Transaction（收支流水）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long PK | 自增 |
| type | Text | expense / income（金额恒为正） |
| amountCents | Long | > 0 |
| categoryId | Long FK | 指向 Category |
| accountId | Long FK | 指向 Account |
| occurredAtMillis | Long | 发生时间（索引） |
| note | Text | 备注，可空 |
| createdAtMillis | Long | 创建时间 |

**Transfer（转账，P1）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long PK | |
| fromAccountId / toAccountId | Long FK | |
| amountCents | Long | |
| occurredAtMillis / note | … | |

**偏好（DataStore，非 SQLite）**：默认账户 id、主题、连续记账开关、快捷模板（JSON 串）、最近金额列表等。

### 5.2 索引建议

- Transaction：`occurredAtMillis`、`categoryId`、`accountId` 各建索引 → 万级流水查询不卡顿

### 5.3 备份文件格式（v1）

JSON 顶层：`{ version, exportedAt, categories[], accounts[], transactions[], transfers[], prefs{} }`
金额字段同用 `amountCents`，保证跨版本可迁移。

### 5.4 口径决策（重要，写死在代码注释里）

- 退款类场景统一记为「收入-退款分类」，**不引入负金额支出**，避免统计歧义

## 6. 统计口径

| 指标 | 定义 |
|---|---|
| 支出 | Σ type=expense（转账除外） |
| 收入 | Σ type=income（转账除外） |
| 结余 | 收入 − 支出 |
| 分类占比 | 该分类支出 ÷ 总支出 |
| 环比 | 本周期 vs 上一等长周期 的增减百分比 |
| 区间 | 自然月 / 自然年 / 自定义闭区间 [start, end] |
| 期初结余 \* | 截至上一周期末的累计结余（= 历史累计收入 − 历史累计支出），跨月滚动用 |
| 累计结余 \* | 期初结余 + 本期结余（可选开关显示） |

> \* 跨月结余相关字段**默认关闭**，仅在统计总览开关开启后显示（见 F3/F8）。

一致性保证：任何周期视图的数字都由明细逐笔实时聚合（Room 查询聚合或内存聚合），**不另存汇总缓存**，从根上杜绝"统计与明细对不上"（市面工具常见病）。

## 9. GitHub 云端开发与构建方案（本机零安装）

> 结论：**可行且推荐**。组合 = GitHub 仓库 +（可选）Codespaces 开发 + GitHub Actions 自动构建 APK。
> 注意：GitHub 只承担"开发与构建"，**App 本体依旧 100% 离线**。

### 9.1 方案 A：GitHub Actions 自动出 APK（主力，必配）

流程：

```
push 代码到 main
   → Actions: ubuntu-latest + JDK17 + Gradle Wrapper
   → 运行 ./gradlew assembleRelease（或 assembleDebug）
   → 上传 APK 到 workflow artifact / 附加到 Release
   → 手机浏览器下载 APK 安装
```

workflow 骨架（正式版随项目骨架一并生成）：

```yaml
name: build-apk
on:
  push:
    branches: [main]
  workflow_dispatch:      # 支持手动触发
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
      - name: Build APK
        run: ./gradlew assembleDebug
      - uses: actions/upload-artifact@v4
        with:
          name: jianji-apk
          path: app/build/outputs/apk/debug/*.apk
```

**签名与升级（务必照做，防丢数据）**：

- CI 每次运行的 debug 签名都会变 → 覆盖安装会提示"签名不一致"（需卸载重装 = **丢数据**）
- 因此必须用**固定的 release 签名**：本地（或 Codespaces）用 `keytool` 生成一次 keystore → base64 编码存入 GitHub 仓库 Secret（如 `ANDROID_KEYSTORE_B64` + 密码 Secret）→ Actions 构建 release APK 时解密签名
- 备份功能（F7）作为第二道保险

### 9.2 方案 B：GitHub Codespaces（可选开发环境）

- 需要改代码时，在浏览器打开云端 VS Code（预装 JDK），可跑 `./gradlew assembleDebug` 验证
- Standard 机型（4 vCPU / 16 GB）对这个小项目足够，卡可临时升 Premium
- 免费额度参考：个人免费账号 Actions 约 2000 分钟/月、Codespaces 约 120 core-小时/月——本项目远远用不完（每次构建约 2–5 分钟）

### 9.3 方案 C：本机 Android Studio（备选）

- 将来若想本地开发，直接 Clone 同一仓库即可，工程完全兼容（标准 Gradle 工程）；云与本地方案可随时切换、互不冲突

### 9.4 安装到手机

- **无需开发者模式**（那只是 USB 调试用）
- 步骤：手机浏览器打开 GitHub 对应构建页 → 下载 APK → 按提示允许"安装未知来源应用"（不同 ROM 提示略异：小米/华为/Oppo 等）
- 国内网络下载 GitHub 慢时：用电脑下载 APK → 数据线 / 微信文件传输 / 网盘 传到手机安装

### 9.5 本方案对"自用"的收益

- 换电脑、重装系统都不影响开发与构建
- 代码、构建产物全自动，未来加功能只改代码 push 一下
